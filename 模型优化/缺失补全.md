# 缺失视图补全最终方案：本地 Attention + Stage/EF

## 1. 方案边界

本项目最终的缺失多视图联邦聚类方案固定为：**客户端本地完整样本锚点注意力补全 + Stage 阶段感知压缩 + 客户端误差反馈**，即配置中的 `missing.method=attention`、`compression.method=stage`、`compression.error_feedback=true`。`system/run_missing.py` 在七个数据集上默认运行 `r∈{0,0.1,0.3,0.5,0.7}`，`seed=42`，50% 稠密载荷比例。完整视图的原两阶段和历史压缩实验保持原样；本文件只约束缺失实验路径。

注意力补全参考 [Wang 等，*Debiased and Denoised Representation Learning for Incomplete Multi-view Clustering*，ICLR 2026](https://openreview.net/pdf?id=Bp3I456do5) 的完整样本参照与表示校正思想，但本项目实现是横向联邦、DEC 聚类和 Stage/EF 传输下的迁移，并未复现该论文的全部损失或结果。因此不能把注意力模块本身称为原创，也不能把两者的实验数值直接比较。

## 2. 缺失掩码与数据隔离

先按现有无标签随机规则把样本划到互不重叠的客户端，再在每个客户端内由数据集名、客户端 ID、种子和名义缺失率生成一次固定 `N_client × V` 布尔掩码。`r` 表示不完整样本的比例；每个被选中的样本恰好随机缺失一个视图，因此实际缺失单元格比例约为 `r/V`，每行至少保留一个可见视图。训练、中心初始化、压缩校准和评估全程使用同一掩码；不根据标签、聚类结果或轮次重抽。

缺失位置的原始值不进入客户端归一化、编码、重构目标、DEC 目标缓存、中心初始化、软簇计数或压缩评分。各客户端只用本地已观察条目估计视图归一化统计；归一化后再将不可见位置置零。标签仅用于最终 ACC、NMI、ARI 计算。`r=0` 也走这条新预处理路径，因此不能直接当作旧完整视图结果的严格复现。

每项 `summary.json` 保存名义和实际缺失样本率、实际缺失单元格率、各视图可见数、每客户端完整样本数和掩码 SHA-256；由配置与种子可重建同一掩码。

## 3. 客户端本地注意力补全

各视图先由独立编码器得到表示。对样本 `i`，仅按掩码内实际可见的视图重新归一化 `view_logits` 融合权重，得到可见共识 `u_i`。客户端从**本地完整样本**编码出最多 `anchor_size=256` 个共识表示作为固定轮内锚点；锚点、单样本表示及注意力权重均不上传。

对不完整样本，以 `u_i` 作 query、完整锚点作 key/value，经默认四头注意力得到校正项 `b_i`，再计算 `s_i=normalize(u_i+b_i)`。原本可见的视图表示保持不变，仅把缺失视图的**表示**填为 `s_i`，最后按全部视图的模型权重融合并送入 DEC 聚类头。这里不恢复原始高维输入。客户端若没有完整样本，安全回退到仅融合可见视图；不能读取其他客户端的锚点或被掩盖原值。

重构和跨视图一致性只在真实可见视图上计算。中心初始化、每轮固定的 DEC 目标缓存、软簇计数、服务端评估均使用相同的最终融合表示。`center_init_round` 之前保持原有的重构与一致性损失；初始化后沿用原两阶段 DEC KL 与均衡损失调度，不增加训练阶段。

## 4. 与 Stage/EF 传输的结合

注意力 Q/K/V 属于普通模型参数，和编码器一同进入现有按样本数 FedAvg 及 Stage 稀疏载荷；聚类中心与簇计数仍按原规则单独聚合。误差反馈残差只留在客户端。压缩校准的稠密参考和候选包使用相同本地样本、可见掩码、锚点及固定 DEC 目标，不使用标签或不可见值。

当前 50% 是**本模型稠密上行载荷比例**，通信统计是单进程模拟的编码字节数，不是实测网络流量或延迟。若未来与其他模型比较，应另做严格相同绝对上行字节的实验。

## 5. 结果与结论边界

正式 Attention＋Stage/EF 的不同缺失率、ACC/NMI/ARI、最佳轮、稳定性、实际上行字节及逐轮历史统一见 [`results-缺失/summary.md`](../results-缺失/summary.md) 和各任务 `summary.json`、`history.json`。根目录汇总只保留这一最终方案；历史其他缺失方法及无压缩结果不属于最终交付。旧的 `results-2阶段/`、`results-压缩/` 不在本次清理范围内。

本次选择是用户指定的研究方案，不等于已证明其在所有数据集或缺失率上具有最优性能。报告时应注明种子、掩码定义、最佳轮/总轮、稳定性和样本级与单元格级两种实际缺失率。注意力源自既有论文；若论文需要论证第二创新点，还须对联邦本地化、DEC 协同或传输优化给出独立且可复验的贡献证据。
