# 两阶段联邦多视图聚类的模型更新压缩方案

> 状态：原始设计已实现首版，并完成固定 50% 上行模型载荷预算的单种子实验。本文保留设计依据；当前 Stage＋误差反馈与 Top-k_ef 的同预算对比见 [`results-压缩/tuning_summary.md`](../results-压缩/tuning_summary.md)。

## 1. 目标与边界

目标是在明确的客户端上行字节预算内，尽量保留当前两阶段联邦多视图聚类的训练效果。各客户端拥有互不重叠的样本子集，但每个样本包含全部视图；真实标签仅用于最终 ACC、NMI、ARI 评估，不能用于校准采样、压缩评分或聚合。

本方案优先处理**客户端上传模型更新**。首版不声称降低服务器下行广播量，也不改变聚类中心初始化和现有中心聚合规则。服务端仍只接收参数更新、中心及簇计数摘要，不接收原始样本、单样本表示、分配矩阵或相似度矩阵。

项目原始代码在 [`clientcluster.py`](../system/flcore/clients/clientcluster.py) 返回完整 `state_dict`，在 [`servercluster.py`](../system/flcore/servers/servercluster.py) 对普通参数做样本数加权聚合，对聚类中心先做 Hungarian 对齐，再按软簇计数聚合。因此，**在完整张量中置零不是通信压缩**；现有实现产生紧凑载荷并记录序列化后的字节数。

## 2. 论文依据与适用范围

参考论文：[Enhancing Communication Compression via Discrepancy-aware Calibration for Federated Learning，ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/file/72235260ae8d57ac42638a26d3b7d089-Paper-Conference.pdf)。论文在客户端随机抽取少量校准样本，利用候选参数被丢弃时的**层输出差异**代替单纯的参数幅值，为 Top-k 稀疏化或 ATOMO 低秩分量排序；实验采用误差反馈。在线性层，单个更新元素 `w[i,j]` 的评分与 `w[i,j]^2 × 输入通道 j 的校准激活能量` 成正比。论文主要在有监督分类模型上实验，不能直接推断它对本项目的聚类指标同样有效。

可借鉴的是“小型本地校准集 + 影响评分 + 固定通信预算 + 误差反馈”。本方案需要额外解决：中心初始化前后目标不同、无标签软分配可能不稳定、视图之间及参数块之间存在相互作用，以及中心参数有特殊聚合语义。

## 3. 当前设想的不足与修改决定

| 不足 | 修改决定 |
|---|---|
| 仅比较单层或单个参数块的输出变化，未必对应聚类目标 | 以现有训练目标在校准集上的退化为主评分，并观察多视图关系与聚类关系 |
| 中心未初始化时比较聚类分配没有意义；初始化后早期软分配仍可能不稳定 | 沿用项目已有的聚类权重调度 `s_t`，逐步引入分配相关评分 |
| 将候选块的独立分数相加，可能忽略块之间的抵消或协同 | 先廉价筛选，再对少量完整压缩方案进行整包复核 |
| 只根据某一视图或本地伪标签评分，可能遗漏跨视图结构或被簇编号扰动 | 比较各视图表示的样本关系；中心初始化后比较 `Q Qᵀ` 表示的软同簇关系 |
| 发送稠密零张量或忽略索引成本，无法证明实际节省 | 使用真实紧凑编码，预算和结果均按编码后的字节数统计 |

这里的“影响聚类”是**无标签代理指标**，不是直接知道哪个上传块能提高全局 NMI。论文结论必须由服务器聚合后的独立评估验证。

## 4. 评分定义

第 `t` 轮客户端从全局模型参数 `θ_t` 出发，训练得到本地更新 `Δ_i`。首个原型可以暂不启用误差反馈；启用时令历史残差为 `e_i`，待压缩有效更新 `u_i = Δ_i + e_i`，压缩结果为 `c_i = C(u_i)`。这里的 `u_i`、`c_i` 只涉及待压缩的普通参数；两个评分模型都装入**同一份训练后的本地聚类中心和小张量**。评分时用相同的本地校准样本 `S_i` 比较 `θ_t + u_i` 与 `θ_t + c_i`，避免训练模式、样本和聚类中心不同造成伪差异。两者均使用 `eval()` 和 `no_grad()`。

建议从下式开始，而非为每个参数设计复杂手工规则：

```text
D_t(c_i) = D_task + λ_view · D_view + s_t · λ_pair · D_pair

D_task = max(0, L_t(θ_t+c_i; S_i) - L_t(θ_t+u_i; S_i))
         / (abs(L_t(θ_t+u_i; S_i)) + ε)

L_t = λ_rec·L_rec + λ_con·L_con
      + s_t·(λ_clu·L_DEC + λ_bal·L_bal)
```

其中 `L_t` 复用当前 [`multiview.py`](../system/flcore/trainmodel/multiview.py) 的损失语义。若使用 DEC 目标分布，完整模型与压缩模型必须对照**同一轮开始时固定的本地目标缓存**，不得分别重算目标。`D_view` 比较两模型在各视图和融合表示上的样本两两余弦相似度矩阵；`D_pair` 比较完整模型与压缩模型的 `Q Qᵀ`，其中 `Q` 为校准样本的软聚类分配。关系矩阵仅在客户端用于评分，不上传。矩阵差异按样本对数量和参考矩阵范数归一化，以免校准样本数改变评分尺度。

中心初始化前设置 `s_t = 0`，完全跳过 `D_pair` 和 DEC 相关项；初始化后沿用当前预训练内的渐增 `s_t`；正式聚类阶段使用 `s_t = 1`。`D_view` 用于保护多视图结构，`D_pair` 在簇编号整体置换时仍保持不变，但二者都只是代理信号；特别是在分配塌缩时，仍需检查现有的簇均衡损失与全局评估。`λ_view`、`λ_pair` 是待消融的超参数，不能根据测试标签逐轮调节。

每轮从客户端本地数据中抽取一次校准集，并让所有候选压缩方案共用它。起点可用论文的约 64 个随机样本；簇数较多的数据集需比较更大的校准集或基于**软分配**的覆盖采样，不能使用真值标签。先检查校准开销，再决定是否启用复杂采样。

## 5. 压缩选择与数据流

1. 客户端正常完成本地训练，计算普通参数的 `Δ_i`。聚类中心、视图权重和其他极小张量首版完整发送；中心初始化前不发送尚未参与训练的中心参数。中心初始化所需的本地 KMeans 中心及计数摘要保持现状。
2. 先用论文的激活感知元素评分或 Top-k 幅值评分产生廉价候选。按视图和层产生少量不同的预算分配方案；每个方案都必须满足**实际编码字节预算**。首版不对每个参数块反复运行完整模型。
3. 在同一校准集上计算少量候选方案的 `D_t`，选择整包评分最低者。这一步能观察多个块同时压缩后的效果；候选数应受限（例如 4–8 个），并单独记录额外计算时间。若收益不足，保留简单排序，取消整包复核。
4. 将选择结果编码为“参数名/形状信息 + 保留位置或块编号 + 数值”的紧凑载荷。小张量可原样发送。索引、头信息、中心及簇计数摘要都计入上行字节；稀疏 COO 与结构化块编码是否更省，按真实编码比较。
5. 服务端以本轮全局模型为基准恢复普通参数更新，再按现有样本数权重聚合。聚类中心仍走原有 Hungarian 对齐、软簇计数加权和动量流程，不把它们当作普通稀疏更新平均。
6. 若启用误差反馈，客户端按 `e_i ← u_i - c_i` 保存未上传的普通参数更新，跨轮、跨未参与轮次保留；中心不纳入该残差。残差只留在客户端，不上传。先比较关闭和开启误差反馈的结果，再决定最终配置。

当前代码是单进程联邦模拟。即使服务器收到紧凑载荷，也只能严谨地称为“**模拟传输的编码字节数下降**”；如需报告真实网络耗时，应另做网络或带宽限制实验。

## 6. 实现顺序与验证门槛

先建立完整上行、下行字节数和每轮计算时间的基线，再实现“固定字节预算的 Top-k + 编码/解码 + 聚合”以验证通信闭环。随后依次加入论文的激活感知排序、阶段感知任务评分、多视图/同簇关系、整包复核，最后评估误差反馈。每一步都要在**相同实际上行字节预算**下比较，避免把“保留 10% 参数”误写成“只传 10% 字节”。

至少记录：每轮及累计上行字节、下行字节、压缩时间、本地训练时间、ACC/NMI/ARI、随机种子、最佳轮与总轮数。先选一个小模型数据集和一个大输入维度数据集做端到端检查，再扩展到七个正式数据集及多个种子。要检查压缩前后载荷恢复一致性、聚类中心及簇计数对齐、中心初始化前后两阶段语义、未参与客户端的残差持久性，以及标签未进入训练与压缩决策。

核心对照为：无压缩、相同字节预算的 Top-k、论文式层输出差异评分、阶段感知评分；随后分别移除 `D_view`、`D_pair`、整包复核和误差反馈做消融。若阶段感知整包方法未在多个数据集上稳定改善“聚类质量—实际字节数”关系，或压缩时间抵消收益，就退回更简单的方案，不强行增加机制。

## 7. 论文表述边界

可研究的主张是：**在无标签、两阶段的联邦多视图聚类中，用训练阶段和聚类关系指导固定字节预算下的模型更新选择**。其中本地校准、激活感知排序、Top-k 和误差反馈都属于已有方法；只有经过对照和消融证明有效的阶段感知目标、跨视图关系保护或整包选择，才适合作为本项目的独立贡献。现有单种子结果尚不能支持“显著提升”或“保证收敛”的表述。

## 8. 首版实现与实测判断

首版已提供真实稀疏索引＋数值编码、服务端恢复、逐轮载荷字节统计，以及 `none`、`topk`、`topk_ef`、`paper`、`stage`、`stage_ef`、`stage_task` 候选。`stage` 用四种候选掩码复核；`stage_ef` 在此基础上增加客户端误差反馈；`stage_task` 移除多视图与软同簇关系项。当前编码把视图权重等极小普通参数与其他参数一并稀疏化，**尚未完成**原设计中“极小张量完整发送”的独立消融；也尚未完成下行压缩、真实网络测速或不同预算的 Pareto 搜索。

正式结果按当前研究方向统一使用 `stage_ef`。在 50% 上行预算、`seed=42` 下，Stage＋反馈相对 `topk_ef` 在 5/7 个数据集的 NMI 更高，但等权平均 NMI 为 0.565782 对 0.568708，累计压缩时间约 249.62 秒对 30.56 秒；两者累计上行模型载荷均约减少 50%。这不是整体性能优势，不能据此声称创新点已被验证。详见 [`results-压缩/tuning_summary.md`](../results-压缩/tuning_summary.md)。

更严格的 20% 上行预算下，三个种子、七数据集配对平均 NMI 为 Stage＋反馈 0.557067、Top-k_ef 0.558226。加大关系评分权重、增加候选和保守切换阈值未形成可信的统一改进；探索记录留在 [`Stage优化实验.md`](../results-压缩/tuning/历史报告/Stage优化实验.md)。正式论文仍需多种子验证，并如实呈现通信、质量和计算代价的权衡。
